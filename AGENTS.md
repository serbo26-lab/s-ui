# Работа с s-ui-node

Go-backend основан на [alireza0/s-ui](https://github.com/alireza0/s-ui). Vue-frontend разрабатывается отдельно: [serbo26-lab/s-ui-frontend-node](https://github.com/serbo26-lab/s-ui-frontend-node), каталог `frontend/` здесь — Git submodule.

- API, Go, базу данных, установщик и релизы меняй в этом репозитории; Vue-интерфейс — в frontend-форке.
- Не подменяй зафиксированный SHA подмодуля веткой `main` во время релизной сборки. Обновляй gitlink отдельным PR.
- Без отдельной задачи не меняй Go module path, пути `/usr/local/s-ui`, имя службы `s-ui`, формат БД и внешние API: на них завязаны работающие установки.
- Установка и обновления должны использовать только `serbo26-lab/s-ui-node`. Не публикуй Docker-образы в реестры оригинального автора.
- Перед PR проверь `gofmt`, `go vet ./...` и `. ./build-tags.sh && go test -tags "$(tags_for test)" ./...`. Для frontend: `cd frontend && npm ci && npm run build`.
- Изменения на production не проверяй. Используй отдельную тестовую среду и резервные копии.
- Сохраняй GPL-3.0, copyright-уведомления и ссылку на оригинальный S-UI.
- Описывай PR по существу: проблема, исправление, проверка, влияние на совместимость.

## Стиль текстов

Перед публикацией README, описания PR, сообщения об изменениях, пользовательские подсказки и документацию редактируй как нормальный человеческий текст: без канцеляризма, шаблонных фраз и искусственной «нейросетевой» структуры. Пиши коротко и по существу; объясняй, что меняется, зачем это нужно и какие есть ограничения. Не украшай технические факты и не обещай проверок, которые не проводились.
